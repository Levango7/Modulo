# F-10 设置 IA + 首启引导（设计稿）

> 状态：**设计已定，实现中**。验收口径来自 `docs/design/FUNCTIONAL-SPEC.md` 的 F-10：
> 「设置独立入口；六个分组；首启三步可跳过；"不再提示"可复位」。
> 这份稿子只回答"长什么样、为什么这么分、状态存在哪、边界在哪"；实现与门禁见 §7。

## 0. 现状是量出来的，不是感觉出来的

- `src/vue/components/SettingsPanel.vue` **452 行、一条滚动列、9 个节**：视觉方向 / 明暗 / 强调色 / 提醒 / 桌面，
  加四个子组件节（方案册 / 备份 / 同步 / 版本）。面板 `max-height: min(86vh, 760px)` —— 文件里已有注释记过
  「1440×900 时内容高 925px、可视只有 640px」那次修复。
- 后果不是"不美观"，是**找不到**：想改多端同步得先滚过三组外观 + 提醒 + 桌面 + 方案册 + 备份。
  54 张卡有搜索（F-09），6 个设置分组却只能靠滚。
- 首启**只有"模板选择器弹一次"**，判定是派生量：`store.ts` 的 `firstRun = usedStarter && !templateId`。
  `usedStarter` 在第一次启动后就被 starter 版面落盘顶掉 ⇒ 它确实只弹一次，但同时意味着
  **没有任何持久化的"已引导过 / 已跳过"状态**：关掉就再也回不去，"不再提示可复位"这条验收无处落地。

## 1. 定位（一句话）

把设置从「一条长滚动列表」改成「**六组 + 侧栏**」；首启变成「**三步向导**」，可跳过、可回放，
**不替用户改任何数据**（选版面那一步点了才应用，且照旧可 `Ctrl+Z` 退回）。

分组的组织原则只有一条：**按"我现在想改什么"分，不按"代码里在哪个组件"分**。
所以「备份 + 同步 + 数据目录」是一组（都是"我的数据在哪、怎么带走"），而不是按组件边界拆成三处。

## 2. 六组结构

| 组 | 组内内容 | 说明 |
|---|---|---|
| **外观** | 视觉方向 / 明暗 / 强调色 | 现有三节原样搬入，**零语义改动** |
| **版面与方案** | 版面模板入口（点开仍是既有的 `TemplatePicker`）+ 方案册（`SchemesSection`） | 模板入口此前在顶栏，设置里给一个同样的入口，省得为了换排法退出设置 |
| **数据** | 完整备份 + 自动备份（`BackupSection`）/ 多端同步（`SyncSection`）/ 数据目录与它的那句"整个目录拷走就是备份" | 原来的「数据目录」提示挂在"桌面"组里 —— 它讲的是数据，不是桌面 |
| **提醒** | 提醒开关 / 系统通知 / 静默时段 / 习惯起点 | 原样 |
| **桌面** | 点关闭收进托盘 / 快捷键与改键 | **`isDesktop` 才出现**（网页版没有托盘与系统级快捷键） |
| **关于** | 版本 + 检查更新（`VersionSection`）/ **重新播放首启引导** | 复位按钮放在这里 —— "不再提示"与"再看一遍"是同一件事的两面 |

网页版 = 五组（无「桌面」）。桌面版 = 六组。

## 3. 线框

```
┌─ 设置 ────────────────────────────────────────────── ✕ ─┐
│ ┌─────────┐ ┌─────────────────────────────────────────┐ │
│ │ 外观   ●│ │ 视觉方向                                │ │
│ │ 版面与方案│ │ [墨纸] [柔光] [亮彩]                    │ │
│ │ 数据    │ │                                         │ │
│ │ 提醒    │ │ 明暗                                    │ │
│ │ 桌面    │ │ [亮色][暗色][跟随系统]                   │ │
│ │ 关于    │ │ 强调色                                  │ │
│ │         │ │ ● ● ● ● ● ●                             │ │
│ └─────────┘ └─────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────┘
左栏 148px（组名 + 当前组左侧 2px 竖条），右栏自适应；面板 560 → 760px
```

- 宽屏：左右两栏（上面这样）。窄屏（≤ 640px）：左栏变**顶部横向滚动的标签条**，不折叠成下拉 ——
  下拉会把"有六组"这个事实藏起来，而 F-10 的验收之一就是"六个分组"。
- `Esc` / 点遮罩 / 右上 ✕ 三条关闭路径保持不变；`useFocusTrap` 继续套在最外层面板上。
- 记住上次停在哪个组（同一会话内即可，**不落盘**：设置页的落点不值得一个存储键，也不进备份）。

## 4. 首启三步

```
第 1 步 / 共 3 步                                    跳过
选一张版面
[ 三张模板卡（按真实格子画的迷你示意图） ]  [先不选]
                                    [ 下一步 → ]
```
- **第 1 步 选版面**：复用 `E.TEMPLATES` 与 `store.applyTemplate`（点一张即时生效，可 `Ctrl+Z` 退回）。
  「先不选」= 继续下一步，不动版面。
- **第 2 步 选外观**：皮肤 + 明暗（复用 `appearance.set`，即时预览 —— 这是引导唯一"看得见好处"的一步）。
- **第 3 步 收尾**：三条"你可能不知道"的事实，每条都点到具体位置：
  ① `Ctrl+Shift+Space` 全局唤起（桌面）；② 关窗是收进托盘不是退出（桌面）；③ 多端同步在「设置 → 数据」，
  用你自己的网盘、不注册账号。→「开始用」。
- **跳过**：每一步右上角都有；`Esc` 同义。跳过与完成**都写 `done: true`** —— 否则每次启动都弹，就成 nag。
  区别只记在 `skipped` 字段里（文案与将来统计用）。
- **回放**：关于组「重新播放首启引导」→ 把 `done` 置 false 并**立即**打开向导（不用重启）。

### 触发口径（为什么老用户不会被打扰）

`showWizard = !stored.done && store.firstRun`。
`store.firstRun` 已经是"版面为空且没挑过模板"的派生量 ⇒ **升级上来的老用户版面非空，永远不会看到它**；
只有真首启（或手动清空版面）才会遇到，且见过一次就被 `done` 挡住。

## 5. 状态

存储键 `modulo.onboarding.v1`（**必须登记进 `DATA_KEYS`** —— 桌面壳的 `get` 只读启动时 hydrate 的镜像，
漏登记的症状是"写得下去、重启读不到"，P0-③ 已经踩过一次）：

```json
{ "done": true, "skipped": false, "at": 1761600000000 }
```

| 事件 | done | skipped | 界面 |
|---|---|---|---|
| 第 3 步「开始用」 | true | false | 关闭向导 |
| 任一步「跳过」/ Esc | true | true | 关闭向导 |
| 关于组「重新播放」 | false | 保留 | 立刻打开向导 |
| 解析失败 / 键不存在 | 视为 `done:false` | false | 真首启才弹 |

**不进备份/同步**：它是"这台机器上的引导是否看过"，跨设备搬过去要么在新机器上跳过引导、要么在老机器上重弹，都不对。
（与 `modulo.reminders.v1` 的口径一致：偏好留各自 key。）

## 6. 明确不做

- **不做设置搜索**：六组的规模不值得；组变多再说（先量，不先建）。
- **不改任何既有设置的语义与存储键**，只搬位置。搬位置也要在 §7 有断言（E2E 逐个点开六组）。
- **引导不写卡片数据**：选版面走既有的 `applyTemplate`（有撤销、有落盘），不另开一条写路径。
- **不引新依赖**：图标用已有的 `lucide-vue-next`。

## 7. 实现与门禁（本批要落的东西）

## 8. 影响面与风险

- 面板宽度 560 → 760，`max-height` 不变；手机上左栏转横向标签条（新增一段 `@media`）。
- 动文件：`SettingsPanel.vue`（重构模板与样式的组织）、`App.vue`（首启一处）、新增 4 个文件 + 2 个测试。
- **与在飞的 #191（`feat/instance-data`）文件零重叠**（它动 `cardData*` / `GridLayout` / `paletteIndex`）。
- 已知取舍：分组导航会让"改一个设置"多一次点击（先点组）。换来的是"要找的东西在第六组"变成一次定位，
  而不是滚过一次 925px 的长条 —— 六组的规模下这笔账是正的。
