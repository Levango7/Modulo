## 4. 数据、契约与读盘策略

**存储与单一真源**

- 配置文档：`ai-settings.v1`（`data/ai-settings.v1.json`，Rust 的 `safe_name` 白名单允许连字符，实测合法）。
  schema 与 `src-tauri/src/ai/settings.rs` 的 `ProviderCfg` 逐一对应：
  `{ providers: [{ id, kind, baseUrl, model }] }`。
- **密钥永不进这份文档**（AC-09）：只在凭据管理器，`ai_providers` 只回 `keyConfigured` 布尔。
- `id`：前端生成，`p-<36 进制毫秒>`，要求非空且在同文档内唯一（Rust 只按 id 查找，不做格式校验）。
- **登记 `DATA_KEYS`**：这一条不是可选项。`createFileStorage.get()` 读的是启动时 `hydrateData` 灌进内存的镜像，
  镜像只装 `DATA_KEYS` 里的键 —— 漏登记的症状是"设置页写着三个服务、重启后一个都不见了"
  （F-10 之前踩过的原样坑）。本期 UI 的**列表展示读镜像**，不靠 `ai_providers` 读盘。

**为什么展示读镜像、探测才调 `ai_providers`**

`ai_providers` 的实现是**对每个 provider 顺序发一次 `GET /models`（各 3s 超时）**。
把它挂在面板挂载上，等于"打开设置要等 N×3 秒"。所以：

- 打开面板：只读 `ai-settings.v1` 文档（镜像，零网络）；
- 点「测试连接」：**先确保文档已落盘**（本页保存是即时的），再调 `ai_providers`，取回的那条 `ready` 就是结果；
  失败/超时也如实显示，不猜原因。

**三条命令的调用形状**（Tauri v2 参数是 camelCase）

| 命令 | 调用 | 返回/失败 |
|---|---|---|
| `ai_providers` | `invoke('ai_providers')` | `[{ id, kind, baseUrl, model, keyConfigured, ready }]`；探测失败只是 `ready:false`，不抛 |
| `ai_set_key` | `invoke('ai_set_key', { providerId, key })` | 空密钥拒绝；成功后只返回 `()` |
| `ai_delete_key` | `invoke('ai_delete_key', { providerId })` | 幂等（没存过也算成功） |

**删除一条 provider 的顺序**：先 `ai_delete_key`（幂等），再改文档删条目。
反过来会留下**凭据库孤儿**（钥匙串里永远躺着一条没人再读的密钥）。

**地址判据两侧同一张表**（前端 `aiSettings.ts` 与 Rust `validate_base_url`）

| 输入 | 结果 |
|---|---|
| `https://api.openai.com/v1` | 放行 |
| `https://`（无主机） | 拒：「模型服务地址缺少主机名」 |
| `http://localhost:11434` | 放行（本机） |
| `http://127.0.0.1:8080/v1` | 放行 |
| `http://ai.example.com` | 拒：「明文 http 只允许本机地址（localhost / 127.0.0.1），云端必须用 https」 |
| `ftp://…` / 不带协议 | 拒：「必须以 https:// 或 http:// 开头」 |
| `https://169.254.169.254/` · `https://router.internal/` | 拒（**本期新增**的黑名单，见下） |

前端这份是**给即时反馈**，真值仍是 Rust：两边不一致时以 Rust 的返回文案为准（原样显示）。
两侧共用同一张用例表（各写各的断言，同一组输入 → 同一结论），与仓库对"两侧判据分叉"的既有处置一致。

## 5. 安全边界（本期落的三条）

1. **AI 出口套保留网段/内网名黑名单**（已拍板）：`validate_base_url` 在"https 放行"之前加一道 ——
   host 是 IP 且落在回环/私网/链路本地/保留段，或域名以 `.local` / `.internal` / `.home.arpa` 等结尾，一律拒；
   **`localhost` / `127.0.0.1` 显式白名单放行**（Ollama 就住这儿）。
   代价要说清：**公司自建的内网 https 网关（10.x / 192.168.x）会被挡住** —— 这是有意的取舍（AI 出口等于"把内容发出去"），
   将来真要支持，得做成显式的"我信任这个内网地址"开关，不能默认放行。
2. **密钥不回显**：输入框 `type=password`、保存后立刻清空、列表只显示「已配置」；E2E 扫 localStorage/文档全文断言无密钥明文
   （口径照 `sync.spec.ts` 那三条的"口令不进任何本机存储"）。
3. **`net-policy.json` 补注记**：AI 出站由 Rust 进程发起，不经过 webview 的 `connect-src` —— 写清楚，
   免得后人看到"清单里没有 AI 域名"以为是漏配（本仓对"单源被误解"有过先例）。

## 10. 实现回填（2026-10-29，一期落地时记 —— 三处与设计稿不一样，如实写）

1. **「保存并测试」拆成「保存」+「测试连接」两个动作**（§3 那张表写的是一个按钮）。保存是即时的、
   探测是网络的（`ai_providers` 一次探全部，N 个 provider 就是 N×3s），混在一起会让"打开设置"变成
   一次联网，也让 E2E 无法断言「保存后是未测试」。代价是用户要点两下 —— 每行那句状态（`○ 未测试`）
   就是在说这件事还没做过。
2. **列表没有「名称」字段**（§3 表单五项 → 四项）。Rust 的 `ProviderCfg` 只有
   `id / kind / baseUrl / model`，加第五个字段就是第二套 schema；显示名取地址里的主机名。
3. **E2E 从 6 条落到 5 条**。第 6 条「会议摘要联动」在这里造不出真判据 —— `meeting_summarize` 在
   Rust 内部直接调 `ai_providers` / `ai_summarize`，桩返回的是假摘要，配没配 provider 对断言没有区别。
   改用一条 Rust 单测钉住「缺配置时的提示指向 设置 → 实验室」（`no_provider_hint`）。另外删除顺序那条
   从「读 IPC 调用顺序」改成「凭据库拒绝时配置必须留着」—— 前者变异过、**不红**（`write_doc` 走串行
   队列，记账顺序与源码顺序无关），后者才是这条纪律真正要防的东西。

数字以 `docs/ARCHITECTURE.md` §12.41 的实测为准（章节号从设计时的 §12.40 顺延，被并发会话占了）。

## 11. 二期实现（2026-10-29 落地时记 —— 与 §9 预告的四处差异，如实写）

1. **§9 担心的高度断言没有被碰到**。46px 是 `flex: none` 的固定占位、展开面板绝对定位在其上，
   画布高度不随开合变化；`layout.spec.ts` 里那几条「1280×800 不用滚」「卡片高度 = span × 行轨」
   全部照旧绿。真正的连带成本在**键盘级联**：`AppKeyLayers` 新增一层 `dockExpanded`（可选字段，
   旧调用方不传即"没有坞"），`keyboard.test.ts` +3 条、`useGlobalKeys.test.ts` +2 条把
   「坞在最底层」「Ctrl+J 在坞不可见时不拦也不动」钉住。
2. **「会话历史」是列表 + 恢复，不是并列多会话**。`ai_history_*` 的四条命令全接上（列表 / 详情 /
   删一条 / 清空），但界面一次只显示一段对话；`conversationId` 只活在组件生命周期里，
   刷新后从「历史」点回来。多会话并列、重命名、搜索都不在本期。
3. **`@卡片` 只引用"用户写进去的字"**。便签（按实例）、待办、四象限、速记、记账、链接、
   倒数日、正计时、习惯、生日、抽签；联网卡 / 计算卡 / 会议速记一律不喂 —— 会议转写另有
   `meeting_summarize` 一条专用路（一期已接），把它当"卡片内容"再喂一次是错的。
   没有可引用内容的卡在引用块里如实写「（这张卡没有可引用的文字内容）」。
4. **E2E 七条里有两条钉的是"后果"而不是"调用"**：「停止」断言后端补的 error 帧把气泡标成
   `已中止` 且**半句还在**（本地先标"已停"会替后端圆谎）；「删除历史」断言桩里盘上那条**真的没了**
   （只读 IPC 记账的话，界面删了、盘上还在这种半成功测不出来）。桩的 `ai_chat` 按 Channel 的
   index 协议真推两帧增量 —— 只推最后一帧的实现会红在"两帧拼成一句"那条上。
5. **`ai_summarize` 仍撤注册**，留给三期（通用「总结这段内容」+ AI 历史作为备份可选大项）。
   本次 `git diff` 里 Rust 只有注册清单与一句文案：本机编译不了（GNU 缺 dlltool），
   编译与打包腿在 CI 桌面 job。

## 12. 三期设计（2026-10-30 起草并落地；入口与持久化两项已拍板）

> **口径已定（2026-10-30）**：AI 历史**维持不进备份/同步**——沿用 10-29 的四决策第④条。
> 因此 §1 表格里三期第二半「AI 历史作为备份『可选大项』」作废，改为"把口径改实"：
> 备份包不收历史（`src/vue/backup.ts` 早已如此），三期只负责把 `history.rs` 与规格书里
> 还写着"进备份"的旧文字改掉，**不动备份格式、不动恢复路径**。

### 12.1 定位（一句话）

把「输入框里的一段字」或「版面里的几张卡」交给已经配好的模型，得到一份 3~5 句的摘要 ——
结果复用二期对话坞承载，不新造面板、不新造卡片。

为什么现在做：`ai_summarize`（`plain` 档）后端完整（会议速记内部正在用），前端零调用点 ⇒
按 F-11② 的「注册 == 调用点」纪律它仍是撤注册状态。三期补上调用点，把这条命令解除撤注册。

### 12.2 入口（推荐 A，开工前请你点头）

**A. 坞内一枚「摘要」动作（推荐）**：发送键左侧加一枚次要按钮，可用条件 = 有引用 chip 或输入框非空。
点它就发一次摘要请求，**不进入对话上下文**。
- 为什么不是"每张卡加个按钮"：主工作台是浏览态，今天没有任何卡片级动作面（卡片操作都在顶栏浮窗清单里）；
  为一个动作新建菜单，成本远大于收益，而且"任意一段文字"仍然需要一个落点，最后会变成两个入口。
- 为什么不是命令面板：面板是全局的，够不到坞里的 chip，用户得先开坞再选卡，反而多两步。

```
展开态（有引用时）
┌ 线程 …………………………………………………………… ┐
│ 引用： [便签 ×] [待办 ×]                                  │
│ ┌───────────────────────────────────────────┐           │
│ │ 输入框（可空：有引用就能摘要）              │  [摘要] [发送] │
│ └───────────────────────────────────────────┘           │
└──────────────────────────────────────────────────────────┘
```

### 12.3 契约与数据流

- **命令**：`ai_summarize(providerId, text, style)` → `{ summary }`。Rust 实现已在，本期只回注册；
  `style` 传 `'plain'`（不传时默认是会议档），`text` 由前端拼好。
- **文本**：新纯函数 `summaryText(chips, draft, excerptOf, max = 2000)`。
  引用块走二期**同一条** `contextBlock`（每张卡 400 字、整块 2000 字封顶、超长加「已截断」）；
  输入框有字就追加在后；两者都空返回 `null`（按钮禁用）。预算不另立一套 —— 二期已经为
  "喂给模型多少字"定过价，三期沿用同一价。
- **结果**：插入一条 assistant 气泡（`data-kind="summary"`），一次性渲染
  （`ai_summarize` 契约是 `stream: false`，不走 `Channel`）。
- **provider**：用坞里当前选中项（二期已有下拉）；缺失走二期同一条提示与「去设置」入口。
- **历史**：**不写** `ai/history.json`（只有 `ai_chat` 写）。气泡上标「摘要 · 不保存」——
  刷新后消失。这与刚定的口径一致：历史不进备份，摘要也不假装有持久化。

### 12.4 状态与错误

- 请求中与对话共用 `busy`（禁止并发），按钮显示「摘要中…」。**没有「停止」**：
  `ai_summarize` 没有取消契约，Rust 侧超时 120 s 兜底；「新对话」会让在途结果作废（token 自增后丢弃）。
- 错误原样落在气泡的 error 态（Rust 的人话文案：连不上 / 超时 / 401）。
- 网页版：坞本身不渲染（二期已按 `isDesktop` 收敛），三期不需要额外分支。

### 12.5 不做（本期边界）

- 摘要不进对话历史、不落盘（见 12.3）。
- 不做流式摘要（契约 `stream: false`；要改先改 Rust 契约与 `net-policy` 预算）。
- 不做「选中文字 → 摘要」（webview 选区没有统一动作位）。
- 不动会议摘要（`meeting_summarize` 专用路已在用，`session.rs` 一行不改）。

### 12.7 风险
