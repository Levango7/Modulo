# F4d 边界规格：Streamable HTTP 传输（条件规格 / 一期不启动）

> **状态：一期决策不变——不做 Streamable HTTP（F4d）。** 本文不是启动令，是一份
> **条件规格**：把"将来若真要开 F4d，必须先满足哪些契约"提前钉成可验收条目，免得
> 那时又边写边改判据、把安全边界当可选项。所有"必须"都是**条件式**——以"决定启动 F4d"
> 为前提；在那一日到来之前，本文不改变 `docs/ARCHITECTURE.md` 里"一期五条"的第②条。
>
> 关联：[架构决策与一期五条](../ARCHITECTURE.md)（搜索"明确不做"）·
> [功能规格](FUNCTIONAL-SPEC.md) · [网络策略真源](../../net-policy.json) ·
> §12.86（stdio 客户端）· §12.89（幂等与安全边界）· §12.93（J1 执行半）。

## 0. 为什么现在写

一期把 MCP 的**传输面**只做到了 stdio（§12.86 客户端 / §12.89 加固 / §12.93 接上消费端）。
架构原文写得很清楚："**② 不做 Streamable HTTP（F4d）**"。但"不做"只是一句否决，
没有说清**将来凭什么算做完**。缺口不在代码，在判据：F4d 一旦被提起，最容易发生的
是——有人拿旧 stdio 的那套判据往 HTTP 上套（`mcpCallMs` 以为是同一把尺子）、把协议
错误和工具失败混成一句、或让出站 URL 绕过私网黑名单。这三条都是本仓已经踩过并
修好的坑（F4b 协议事实、F3 B1 双闸门、`validate_base_url` 私网表），F4d 必须继承，
不能重新交学费。

本文把这些坑写成**硬边条件**：不是"建议如何"，而是"不满足即不许合入"。

## 1. 一期决策的边界（本文不动它）

原文（架构"明确不做（一期五条）"）：

> ① 不建连接、不 spawn（F4c）；② 不做 Streamable HTTP（F4d）；③ 不做权限确认；
> ④ 不进备份 / 多端同步；⑤ 不做 `env` 与私密值。

需要如实标注的时间差：五条写于 stdio 客户端之前，**其中①③已被后续笔实现**
（F4c stdio 建连 + J1 确认闸门，见 §12.86 / §12.93）。**②F4d 没有**，本文所列条件
全部以"②被正式解除"为前提；在此之前 F4d 仍不属于一期范围，本文不构成开工依据。
④⑤（不进备份同步、不做 env/私密值）对 F4d **继续成立**，且被本文 §3、§5 重新约束。

## 2. 启动闸门（决定开 F4d 之前必须先答完的四问）

这四问是**决策前置**，不是实现细节。任何一问答不出，F4d 不许进实现笔：

1. **为什么 stdio 不够？** 必须写明一个 stdio 做不到、HTTP 才能解决的真实场景
   （例如：远端托管、多客户端共享同一 server、无本地进程权限的环境）。"更现代"
   "规范推荐"不算理由。
2. **谁出网、走哪条策略？** WebView 的 `fetch` 受 CSP `connect-src` 约束，而那份清单
   由 `net-policy.json` 的固定域名生成——"用户自带的任意主机"进不了表（架构 3004 /
   3021 行）。所以 F4d 若走浏览器 fetch，**用户自填的 server URL 会被 CSP 实拦**；
   若走 Rust 出站（reqwest 路径），则必须复用 §4 的私网闸门。启动前先选死是哪条路，
   不许两套并存。
3. **会话与确认态放哪？** stdio 的确认态只在前端内存（Rust 无查询命令、重启两端同清，
   §12.93）。HTTP 会话是否引入服务端会话 id？若引入，它和"确认态不落盘"如何共存，
   必须先答。
4. **超时用哪把尺子？** `mcpCallMs`（30s）是**单次 stdio 工具往返**的墙钟上限，语义绑
   死在"子进程一次请求-响应"。HTTP 有连接、首字节、流三种时间尺度，直接复用 30s
   是错的；必须先定义映射，见 §5。

## 3. 协议契约（若启动，逐条必须成立）

| # | 契约 | 验收判据（不满足即 blocking） |
|---|------|------------------------------|
| P1 | 握手与版本协商显式化 | 首条请求带协议版本与能力声明；服务端返回不认识的版本/能力时**明确报错**，不许静默按旧版处理。 |
| P2 | 会话 id 与连接解耦 | 会话标识由服务端下发、客户端回送；连接断开重连后会话可恢复或明确重建，不许"断线即失忆但界面假装还记得"。 |
| P3 | 服务端推送可选且可关 | 若走流式响应，客户端能在不支持流的环境下降级为普通请求-响应；降级路径与流式路径**输出同一形状的结果**。 |
| P4 | 工具清单形状与本地同源 | 远端工具清单折进 `tools` 时，走 J1 已有的 `mergeToolLists` 与白名单逻辑（§12.93），**不造第二套清单**——两套并存是最容易分叉的形态。 |
| P5 | 一轮只算一次清单 | 与 §12.93 同源：每轮开始前 `gather` 一次，异步往返后**重判 token / aborted**，续跑轮复用同一份，不许工具在模型视野里消失。 |

## 4. 安全边界（若启动，全部是硬边）

**出站 URL 必须过既有私网闸门，不新造第二套判据。** 仓内已有
`src-tauri/src/ai/protocol.rs` 的 `validate_base_url`（第 42 行）：scheme 白名单 +
私网/保留地址黑名单，黑名单**直接复用 `net::blocked_reason`**（与 feeds 抓取同一张表，
本机三写法除外），并挡住 userinfo 绕过（测试第 343 行：
`https://evil.com@169.254.169.254/latest` 必须被拒）。F4d 的每个出站目标必须走这道门：

- **同一张表**：不许为 HTTP 传输单列一份黑名单（F3 B1 的教训——两个闸门迟早分叉）。
- **先校验再连接**：`validate_base_url` 在发起任何连接**之前**执行；重定向后的新目标
  **重新过闸**（否则一个合法外链 302 到 `169.254.169.254` 就穿了）。
- **userinfo 不算主机名**：`@` 前的字符串不得用来骗过"看起来是公网域名"的判断。
- **DNS 重绑定**：校验时的解析结果与连接时的目标必须一致；若做不到，如实标注为
  已知缺口并给出替代约束（如只允许 IP 字面量或固定端口白名单），不许假装已防住。

**注入面（继承 §12.89 加固）**：URL、server id、工具名、参数仍走既有字符闸门——
控制字符、注入式 id、非布尔开关一律拒收；坏条目丢弃、好条目留下，不清空整份。
盘上条目与用户手填**走同一道闸门**，不造第二套。

**不代装、不代管密钥（④⑤继续成立）**：Modulo 不带 server、不装 Node/Python；
`env` 与私密值不在 F4d 范围——真要连远端且需要凭据时，与 keyring 一起设计，
不留没人读的字段。命令/参数不经过 shell（不支持 `|`、`&&`、变量展开）这条对
HTTP 传输同样成立。

## 5. 错误分类与超时（两条最易复发的历史坑）

**两类失败分开报，绝不合流。** 这是 F4b 协议事实，stdio 已守、F4d 必须继承：

- **协议错误**：RPC 层的 `error`，字段存在性与类型严查（`protocol.rs:63 parse_rpc_error`
  要求 `error` 是对象、`error.code` / `error.message` 存在且类型正确；`result` 与
  `error` 并存是最根本的矛盾形状，优先报，见 `protocol.rs:115`）。**绝不用
  `.unwrap_or(缺省)` 把畸形响应伪装成"成功、零输出"**。
- **工具失败**：工具跑了但返回失败，是 `result.isError:true` 那一支，是**业务结果**
  不是协议故障。
- **连不上 / 网页版没有桌面壳**：第三类，与上面两类都不同（J1 的 `MCP_OFFLINE`）。
  F4d 里"HTTP 出站被 CSP 拦""目标被私网闸门拒""连接超时"都要落进这一类，
  并说清该修哪一头，不许混成一句"失败"。
  **其中"被私网闸门拒"必须单独成句**——用户要改的是 server 地址，不是重试。

**超时不是同一把尺子。** `net-policy.json` 的 `timeouts.mcpCallMs = 30000` 语义是
**单次 stdio 往返墙钟上限**（notes 原文："挡的是一个工具卡死不返回、把整轮对话钉住"）。
F4d 若启动，必须在 `net-policy.json` **单源**里新增明确键（如连接/首字节/流空闲各一档），
并遵循仓内既有纪律：改单源 → 跑 `node scripts/gen-net-policy.mjs` 重新生成 → 跑
`node scripts/net-policy-check.mjs`（CI 同序）。**消费点必须被钉住**——像
`mcpCallMs` 那样用 `wired` 断言分别钉注入点与判定点，防"定义了常量不参与判定"。
不许在 F4d 代码里手抄一个 30000。

## 6. 明确不做（即便启动 F4d，这些也不在其内）

- 不做"用 HTTP 替代本地白名单工具"——本地 10 条白名单工具一支不动（§12.93 纪律）。
- 不进备份 / 多端同步（④⑤）：server 地址与凭据绑定这台机器的网络环境，搬走多半跑不起来。
- 不做 `env` 与私密值，不留空字段会造成"已经支持"的错觉。
- 不新造工具清单、不新造黑名单、不新造超时常量——三者都复用单源/既有纯层。
- 不把协议错误降级成工具失败，不把任何畸形响应用缺省值洗白。
