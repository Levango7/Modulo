## 3. 缺口与验收（P0 = 产品可用性底线）

### F-01 同种卡多实例（P0）
- **现状**：`store.ts` 的 `available` 只列未放置卡 ⇒ 一个待办清单、一个时钟、一块看板。
- **分两阶段**（2026-10-20 实现时发现的约束：`CardData` 是**单例结构**——一个 `todos`、
  一个 `sticky`，卡组件靠 `inject(cardData)` 共享，并不是按卡 keyed）：
  - **阶段 1（已落地）**：版面层多开。实例 id 与模块 id 分离（`module` 字段），
    第二张起用 `模块:2`；两个实例**共享同一份内容**（两个待办卡 = 同一清单的两个视图）。
    已验：引擎 `addItem(instanceId)`、`moduleIdOf` 贯穿投影/校验/行折叠/缩放/形态、
    浮窗按实例读模块、模块库不再隐藏已放置卡。
  - **阶段 2（待做）**：把记录类卡（便签/待办/速记/记账/四象限/习惯/倒数日）的数据
    按实例拆开，卡组件从 `inject(cardData)` 改为"按实例取切片"，并做数据迁移。
- **阶段 1 验收（已满足）**：
  1. 同一模块放两张，id 为 `模块` 与 `模块:2`，第二个实例带 `module` 归属（单测）；
  2. 旧存档/模板/单实例的形状逐字不变（第一实例不写 `module`，序列化/投影输出不变）；
  3. 折叠→展开、缩放、切形态、浮窗都能正确解析模块（引擎与行容器单测覆盖）。
- **阶段 2 验收（待做）**：两个实例内容互不影响；数据迁移夹具 v1→v2 roundtrip；
  命令面板能定位到**正确实例**；备份导出/恢复两实例都在。

### F-02 内容级撤销（P0，✅ 已落地 2026-10-20）
- **现状（改造前）**：撤销只覆盖版面（`store.ts` 历史栈），便签/待办/速记/记账误删不可恢复。
- **落地**：`src/vue/contentHistory.ts` —— `CardData` 整份快照 + 环形 50 步；
  一段连续输入按 500ms 窗口合并成一步；撤销/重做整份回填且保留顶层 reactive 对象。
  App 的 `undoLatest()` 按时间戳路由：编辑态撤版面、工作台态撤内容，一边没得撤退到另一边；
  输入框内不拦 Ctrl+Z（保留浏览器原生撤销）。
- **验收（已满足）**：
  1. 删除一条待办 → `Ctrl+Z` 恢复，再 `Ctrl+Shift+Z` 再删（`tests/vue/contentHistory.test.ts`）；
  2. 连续输入 1 秒内合并为一条历史（同上「一段连续输入合并成一步」）；
  3. 历史上限（50）生效，新改动清空重做栈；
  4. 直接赋值与数组变更都被记录（覆盖 `v-model` 路径）；
  5. 撤销/重做不制造新历史（不会套娃）。
- **写入防抖（2026-10-21 已落地）**：`cardData` 300ms 合并窗口，`pagehide` / `beforeunload` 时冲刷，
  已有 E2E「输入后立刻刷新不丢字」；`flush()` 暴露给调用方。
- **缺陷与修复（2026-10-29，E2E 抓出来的）**：回填写的是 `toRaw(state)` —— 直接写原始对象**不过 Proxy，
  一个依赖都不触发** ⇒ 撤销/重做之后界面不刷新、`cardData` 的落盘 watch 也不响，**刷新一下撤销就蒸发**。
  单测读的是 `state` 本身（代理读拿得到新值），所以上面那 5 条验收一直是绿的；只有端到端看得见。
  修：回填改成走代理（仍是"删键再赋值、保留同一个 reactive 引用"，只是删与写都过 Proxy），
  并加第 6 条验收（下面）与 `tests/e2e/undo.spec.ts` 三条。经过与判据见 `docs/ARCHITECTURE.md` §12.38。
  6. **回填必须触发依赖**：deep + sync 的观察者在 `undo()` / `redo()` 之后要响（界面与落盘都靠这一下）。

### F-03 完整备份（P0，✅ 已落地 2026-10-20）
- **现状（改造前）**：包内内容是全的（`buildBackup` 导出整份 `CardData`），但
  **`confirmRestore` 只回填便签 / 待办 / 速记 / 倒数日四个字段** —— 导出是全的、恢复是残的，
  记账、四象限、习惯、生日、链接、订阅、自选、自定卡静默丢失。`appearance`、`template`
  根本不在包里；**密钥类设置不得导出**。
- **落地**：
  1. `applyCardData()` 整份回填（先 `sanitizeCardData` 清洗，再逐键**深拷贝**回同一个
     reactive 对象 —— 组件持有的是同一引用，不重挂；不深拷贝会让备份与现场共享数组引用）；
  2. `BACKUP_VERSION` 1 → **2**，新增 `settings` 段：`appearance`（皮肤/明暗/密度）+ `template`；
  3. 恢复提示逐项报数（版面模块数、待办/速记条数、记账笔数、外观设置）。
- **刻意不收**（写在 `backup.ts` 的类型注释里，不是漏掉）：`shell.v1`（全局快捷键要在 Rust 侧
  重新注册，写进去不等于生效，只会制造"看起来恢复了"的假象）、`ai-settings.v1`（密钥）、
  截图 / 会议 / AI 历史（体积与隐私，需要"可选大项"的单独设计）。其中**会议转写 2026-10-28 起有
  独立的导出入口**（`meeting_get` → 纯函数算文本 → `.txt` 落盘，不进备份包、零新命令，
  见 ARCHITECTURE §12.36）—— 「能带出去」与「进备份包」分两步走，前者不卡后者。
- **验收（已满足）**：
  1. 导出→解析→确认→回填后，逐字段核对内容都在（`tests/vue/useBackup.test.ts` 的"整份恢复"用例
     在旧实现上必红）；设置段经回调套上（外观与模板各一条断言）；
  2. 包内不含 token / API key（序列化结果扫描，沿用既有密钥测试）；
  3. v1 老备份仍可导入（`BACKUP_VERSION` 只影响是否提示"没有设置段"）；
  4. `buildBackup` 对每个数组字段都真执行过逐条拷贝（夹具里 `watch`/`endpoints`/`launch`
     曾一直是空数组，那几行从没被执行 —— 本轮补上真数据）。
- **未做**：截图 / AI 历史作为可选大项。会议则走了**独立导出**那一步（2026-10-28：列表行与详情页
  两处入口、导出的文件名与文案由纯判定层算，见 ARCHITECTURE §12.36）—— "可选大项"的包内口径
  （体积计量、默认勾选、AI 历史牵涉 F-12）尚未定，定下来之前先用不进包的出口把「带得出去」兑现。
  （写入防抖已在 2026-10-21 落地）

### F-04 自动备份（P0，✅ 已落地 2026-10-20）
- **落地**：环形 **7 槽**（`modulo.autobackup.slot.<n>.v1` + 一份索引），触发点三类 + 手动：
  **每日首次启动**（距最近一份 ≥24h）、**恢复动作之前**（`pre-restore`，覆盖现场前唯一的反悔路径）、
  **应用版本变化后的首次启动**（`pre-upgrade`）；没有自动备份时启动建基线。
  **只存桌面**：网页版 `localStorage` 有配额，不适合放 7 份整包。
  **不做定时器**：判定挂在"打开应用"这个动作上 —— 常驻心跳没人看，还多一个会漏的洞。
- 索引是盘上的不可信数据：逐项校验，坏条目丢掉而不是整份报废；写失败返回 false，
  **不阻塞任何用户动作**。
- **代价写在这里**：桌面适配器"启动 hydrate 成内存镜像、之后 `get` 只读镜像"，所以索引与 7 个槽
  必须进 `DATA_KEYS`（`src/vue/fileStorage.ts`），于是这 7 份整包会随启动一起读进内存。
  按 `cardData` 的清洗上限（条目 200 / 记账 2000 行 / 自定卡 16 KiB × 8）估，最坏几 MB 量级 ——
  相对"漏登记导致重启读不到、每次启动重建基线并洗掉 7 份"，这个代价愿意付。
  漏登记**不报错**，所以 `tests/vue/useBackup.test.ts` 里那条把整条链跑真的用例是唯一的守法。
- **验收（已满足）**：旋转 8→7 只留最新 7 份（单测）；每日/换版/无动作三种判定各一条；
  槽内容读不出来时给明确提示且不动任何东西；设置面板列出时间 / 触发原因 / 大小 / 当时的应用版本
  并可一键恢复到确认块。顺带修掉一个真 bug：面板此前不在挂载时刷新列表，刚生成的自动备份
  要用户手动点一次"刷新"才出现。
- **面板链 E2E（2026-10-21 补，此前登记的「未做」销账；2026-10-29 再加两条 → **7 条**）**：`tests/e2e/backup.spec.ts`
  启动建基线后开面板即见（**不点「刷新列表」**，钉住 P0-③ 修的挂载刷新）、「立即备份」后索引与槽经
  `write_doc` 真的落盘、改过数据后「恢复这份」确认块逐项对上事实再整份回填（**读盘断言**回到备份时点；
  恢复前自动留的 pre-restore 现场存的是**改过的那份**）、取消路径盘上数据字节级 + 索引深相等、
  索引在槽不在时明确提示且不改任何东西。**勘误**：本条原写「补它要先扩 `tests/e2e/tauri-stub.js`」——
  实际 `read_doc`/`write_doc` 与 `__TAURI_INTERNALS__` 自 2026-10-17 会议历史那批起就在桩里，
  本次**零扩桩**。旋转 8→7 仍只由单测覆盖（`useBackup.test.ts`）：E2E 按「面板层可见行为」取舍，不重复造。
- **启动判定的 E2E（2026-10-29 补）**：每日 / 换版两种判定此前只有单测（注入 `at` 与 `app`）—— 单测测的是
  `initAutoBackup` 这个纯判定，而"启动那一刻真的跑了、且只跑一份"还取决于挂载时机、hydrate 有没有把种下去的
  索引搬到盘上、界面列表有没有跟上。两条用**种索引**逼出来（不冻时钟、产品代码零改动）：每日 —— 种 25h 前的
  那份，断言旧的留着、新的落到下一个空槽（环形没满时不覆盖最老的）；换版 —— 两个条件同时成立，断言**只补
  一份**（"早退"的机械证据：把 `pre-upgrade` 的 `return` 去掉就变三份）。两条窄变异实测都红在目标用例上。

### F-05 提醒与系统通知（P0，阶段 1 + 阶段 2 ✅ 已落地 2026-10-21；深链受平台限制，见下）
- **现状（改造前）**：全仓无 notification 能力；倒数日/生日/习惯/待办只能"看"。
- **阶段 1（已落地）**：`src/vue/reminders.ts` 纯判定（`now` 注入）+ `src/vue/useReminders.ts` 胶水。
  规则三条：倒数日就是今天 / 生日就是今天（闰日平年落 2/28，跟引擎走）/ 习惯过了设定时刻没打卡。
  **不做待办到期提醒**：`Todo` 没有截止日期字段 —— 不编不存在的东西。
  投递 = 顶栏下方一条可收起的**提醒横幅**；同一件事**一天只提醒一次**（稳定 key + 当日已提醒表落盘）；
  **静默时段只压投递、不压事实**（静默结束后同一天内补弹）。**默认不静默**（起止相同 = 关闭）——
  静默跨午夜时当天不再补，对"就是今天"的事件等于吞掉，所以让用户自己开。设置存本机不进备份。
- **阶段 1 验收（已满足）**：注入 now 跨越到期点恰好一条（单测）；重启不重复、且跨桌面 hydrate
  链（单测把 `createFileStorage → hydrateData → 新实例` 跑真）；静默内不弹、静默后补弹；
  坏存储/写失败不拦投递；E2E 种子倒数日 → 横幅出现 → 收起 → 刷新不再弹。
- **阶段 2（已落地，2026-10-21）**：桌面壳接 `tauri-plugin-notification`（Cargo + npm +
  capabilities 的 `notification:default`）；动态 import，网页版不进包。权限被拒 / 插件加载失败 /
  发送抛错一律静默降级（横幅兜底）。设置里多一个「同时发系统通知」开关（默认开、只桌面可见）。
  判定、去重、静默时段与阶段 1 完全共用 —— 只换了投递实现。
- **做不到的一条（写清楚，不假装完成）**：**点通知回到对应卡在 Windows 上做不到**。插件文档写明
  交互式 action（回传"点了哪一条"）只有移动端有；Windows 只能得到系统默认的"点一下把应用带到前台"。
  真深链要自己做 Toast COM 激活或换通道，单列。另一个已知显示事实：**开发态** Toast 用的是
  `powershell.exe` 的身份与图标，装成安装包后才显示 Modulo（插件文档原话）。
- **仍未做**：卡内角标（倒数日卡已在当天高亮、生日列表在当天带图标、习惯卡显示连续天数 ——
  这三处已是"看得见"，独立角标需要和现有视觉一起定形状）。

### F-06 数据迁移框架（P0，✅ 已落地 2026-10-21）
- **现状（改造前）**：`SCHEMA_VERSION=1`、`MIGRATIONS` 空表；版面读盘时迁移但**结果不落盘**；
  `schemes` / `cardData` 没有迁移入口；迁移前无快照；`migrate()` 注释承诺"不抛"但没兜住抛错。
- **落地**：
  1. `migrateWith(raw, table, to)` 参数化迁移表（版面复用 `MIGRATIONS`；方案册 / 卡片内容各一张空表）；
  2. `src/vue/migrate.ts`：**store 读盘之前**统一迁移并**写回**，加第一条迁移时只填一行；
  3. **先快照后写回**：原文进 `modulo.migration.backup.v1`（最多 3 次现场），快照写不出就不迁移；
  4. 失败语义：迁移函数抛错 / 某 key 写失败 / JSON 坏 —— 原件不动，提示进界面（迁移提示首次接了 UI）。
- **验收（已满足）**：夹具 v1 → v2 经注入表跑通并读回一致；迁移函数抛错时**原文件不变**且不抛；
  快照写失败时一条都不改；某个 key 写失败不影响其余；幂等（第二次不写盘、不新增快照）；

### F-07 网络策略单一来源（P0，安全）✅ 已落地（2026-10-22）

- **单源**：仓根 `net-policy.json`（`version: 1`）。超时五档、响应体上限两个、URL 上限一个、
  允许外连的域名清单一份 —— 每个数字只在它里面出现一次。
- **统一了这六处**（此前各写各的、靠注释维系同源）：
  1. `packages/engine/src/http.ts` 的注释写「响应上限与超时沿用 `net.rs`（1 MiB / **5s**）」，
     而 `src-tauri/src/net.rs` 实际是 **10s** —— 注释里的 5s 是谎言，现改为「见 `net-policy.json`，
     本文件不再抄数字」。
  2. `src-tauri/tauri.conf.json` 的 `csp` 与 `devCsp` 两条 `connect-src` 都缺
     `https://push2.eastmoney.com` —— **真 bug**：`packages/engine/src/stock.ts` 的 `QUOTES_URL`
     正是该域，桌面壳里股票卡取数被 CSP 实拦；网页版没有 CSP，所以它一直没暴露。两条都补上。
  3. `src/vue/useRemote.ts` / `src/vue/useWeather.ts` / `src/vue/useUpdateCheck.ts` 三处各手抄
     `8000` → 同读 `FETCH_TIMEOUT_MS`。
  4. `packages/engine/src/http.ts` 的 `MAX_HTTP_URL = 300` 与 `packages/engine/src/watch.ts`
     的 `MAX_URL = 300` → 同读 `MAX_URL_LENGTH`（此前靠一行注释「与 watch 同一 URL 上限」维系）。
  5. `src-tauri/src/ai/openai_compat.rs` 的 120s（摘要）/ 3s（探活）/ 5s（连接）三档 →
     同读单源。前端此前没有对应常量，现在两侧同一口径。
  6. `src-tauri/src/net.rs` 的 1 MiB 与 `src-tauri/src/feeds.rs` 的 256 KiB → 同读单源。
- **⑥ 号的分类结论（先分类再动手）**：256 KiB（feed）与 1 MiB（网页）判为**有意差异**，两个名字
  分别保留，理由写进 `net-policy.json` 的 `notes.feedBodyBytes` 与
  `src-tauri/src/net_policy.rs` 的 `Limits::feed_body_bytes` —— feed 是用户订阅的第三方全文，
  走独立解析路径且一次解析多份（名单可能几十条），单个源体量小、数量多；网页取数是单条、一次
  一目的地。统一成同一个数会让「一次刷新 40 个订阅」的峰值内存涨四倍。**没有为了统一而统一**，
  并有一条单测钉住「feed < 网页且恰好 4 倍」。
- **三侧各自的消费方式**：
  - **引擎 / 前端**读 `packages/engine/src/netPolicy.generated.ts` —— 由
    `scripts/gen-net-policy.mjs` 生成且**入库**（引擎包要能独立构建，不能依赖消费侧跑过生成）。
  - **桌面壳 Rust** 读 `src-tauri/src/net_policy.rs` —— `include_str!("../../net-policy.json")`
    编译期内嵌 + `LazyLock` 解析；解析失败直接 panic，**不回落旧数字**（回落正是这次要消灭的形状）。
  - **CSP** 由同一份域名清单生成，写回 `src-tauri/tauri.conf.json` 的 `csp` / `devCsp`
    （只替换 `connect-src` 段，幂等），并挂在 `beforeDevCommand` / `beforeBuildCommand` 上。
- **验收**：`node scripts/net-policy-check.mjs` **45/45** 项断言通过（单源 ↔ 生成产物 ↔ Rust 四个
  消费点 ↔ 两条 CSP，逐字比对；任一漂移即红，已挂进 `.github/workflows/ci.yml` 的 `verify` job）；
  `tests/engine/netPolicy.test.ts` **6 条**；`tests/release/csp.test.ts` 的域名清单已把东财纳入
  （②号 bug 的回归钉）；`vue-tsc` 与 `tsc --noEmit` 都干净。
- **未做**：「股票卡在桌面壳里实际取到数」这条验收**没有真机冒烟** —— Rust 腿本机编不了
  （GNU 缺 `dlltool.exe`；MSVC 的 `link.exe` 被 Git Bash 的 coreutils `link` 抢到），
  以 CI 的桌面壳 job 为准。CSP 字符串本身已由那 45 项断言逐字钉住。
