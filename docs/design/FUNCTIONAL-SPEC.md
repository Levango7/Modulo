## 3. 缺口与验收（P0 = 产品可用性底线）

### F-01 同种卡多实例（P0）
- **现状**：`store.ts` 的 `available` 只列未放置卡 ⇒ 一个待办清单、一个时钟、一块看板。
- **分两阶段**（2026-10-20 实现时发现的约束：`CardData` 是**单例结构**——一个 `todos`、
  一个 `sticky`，卡组件靠 `inject(cardData)` 共享，并不是按卡 keyed）：
  - **阶段 1（已落地）**：版面层多开。实例 id 与模块 id 分离（`module` 字段），
    第二张起用 `模块:2`；两个实例**共享同一份内容**（两个待办卡 = 同一清单的两个视图）。
    已验：引擎 `addItem(instanceId)`、`moduleIdOf` 贯穿投影/校验/行折叠/缩放/形态、
    浮窗按实例读模块、模块库不再隐藏已放置卡。
  - **阶段 2（待做）**：把记录类卡（便签/待办/速记/记账/四象限/习惯/倒数日）的数据
    按实例拆开，卡组件从 `inject(cardData)` 改为"按实例取切片"，并做数据迁移。
- **阶段 1 验收（已满足）**：
  1. 同一模块放两张，id 为 `模块` 与 `模块:2`，第二个实例带 `module` 归属（单测）；
  2. 旧存档/模板/单实例的形状逐字不变（第一实例不写 `module`，序列化/投影输出不变）；
  3. 折叠→展开、缩放、切形态、浮窗都能正确解析模块（引擎与行容器单测覆盖）。
- **阶段 2 验收（待做）**：两个实例内容互不影响；数据迁移夹具 v1→v2 roundtrip；
  命令面板能定位到**正确实例**；备份导出/恢复两实例都在。

### F-02 内容级撤销（P0，✅ 已落地 2026-10-20）
- **现状（改造前）**：撤销只覆盖版面（`store.ts` 历史栈），便签/待办/速记/记账误删不可恢复。
- **落地**：`src/vue/contentHistory.ts` —— `CardData` 整份快照 + 环形 50 步；
  一段连续输入按 500ms 窗口合并成一步；撤销/重做整份回填且保留顶层 reactive 对象。
  App 的 `undoLatest()` 按时间戳路由：编辑态撤版面、工作台态撤内容，一边没得撤退到另一边；
  输入框内不拦 Ctrl+Z（保留浏览器原生撤销）。
- **验收（已满足）**：
  1. 删除一条待办 → `Ctrl+Z` 恢复，再 `Ctrl+Shift+Z` 再删（`tests/vue/contentHistory.test.ts`）；
  2. 连续输入 1 秒内合并为一条历史（同上「一段连续输入合并成一步」）；
  3. 历史上限（50）生效，新改动清空重做栈；
  4. 直接赋值与数组变更都被记录（覆盖 `v-model` 路径）；
  5. 撤销/重做不制造新历史（不会套娃）。
- **未做**：写入防抖（深监听仍每改必写盘）—— 与 E2E「输入后立刻刷新」有竞态，单独一笔。

### F-03 完整备份（P0，✅ 已落地 2026-10-20）
- **现状（改造前）**：包内内容是全的（`buildBackup` 导出整份 `CardData`），但
  **`confirmRestore` 只回填便签 / 待办 / 速记 / 倒数日四个字段** —— 导出是全的、恢复是残的，
  记账、四象限、习惯、生日、链接、订阅、自选、自定卡静默丢失。`appearance`、`template`
  根本不在包里；**密钥类设置不得导出**。
- **落地**：
  1. `applyCardData()` 整份回填（先 `sanitizeCardData` 清洗，再逐键**深拷贝**回同一个
     reactive 对象 —— 组件持有的是同一引用，不重挂；不深拷贝会让备份与现场共享数组引用）；
  2. `BACKUP_VERSION` 1 → **2**，新增 `settings` 段：`appearance`（皮肤/明暗/密度）+ `template`；
  3. 恢复提示逐项报数（版面模块数、待办/速记条数、记账笔数、外观设置）。
- **刻意不收**（写在 `backup.ts` 的类型注释里，不是漏掉）：`shell.v1`（全局快捷键要在 Rust 侧
  重新注册，写进去不等于生效，只会制造"看起来恢复了"的假象）、`ai-settings.v1`（密钥）、
  截图 / 会议 / AI 历史（体积与隐私，需要"可选大项"的单独设计）。
- **验收（已满足）**：
  1. 导出→解析→确认→回填后，逐字段核对内容都在（`tests/vue/useBackup.test.ts` 的"整份恢复"用例
     在旧实现上必红）；设置段经回调套上（外观与模板各一条断言）；
  2. 包内不含 token / API key（序列化结果扫描，沿用既有密钥测试）；
  3. v1 老备份仍可导入（`BACKUP_VERSION` 只影响是否提示"没有设置段"）；
  4. `buildBackup` 对每个数组字段都真执行过逐条拷贝（夹具里 `watch`/`endpoints`/`launch`
     曾一直是空数组，那几行从没被执行 —— 本轮补上真数据）。
- **未做**：截图 / 会议作为可选大项；写入防抖。

### F-04 自动备份（P0，✅ 已落地 2026-10-20）
- **落地**：环形 **7 槽**（`modulo.autobackup.slot.<n>.v1` + 一份索引），触发点三类 + 手动：
  **每日首次启动**（距最近一份 ≥24h）、**恢复动作之前**（`pre-restore`，覆盖现场前唯一的反悔路径）、
  **应用版本变化后的首次启动**（`pre-upgrade`）；没有自动备份时启动建基线。
  **只存桌面**：网页版 `localStorage` 有配额，不适合放 7 份整包。
  **不做定时器**：判定挂在"打开应用"这个动作上 —— 常驻心跳没人看，还多一个会漏的洞。
- 索引是盘上的不可信数据：逐项校验，坏条目丢掉而不是整份报废；写失败返回 false，
  **不阻塞任何用户动作**。
- **代价写在这里**：桌面适配器"启动 hydrate 成内存镜像、之后 `get` 只读镜像"，所以索引与 7 个槽
  必须进 `DATA_KEYS`（`src/vue/fileStorage.ts`），于是这 7 份整包会随启动一起读进内存。
  按 `cardData` 的清洗上限（条目 200 / 记账 2000 行 / 自定卡 16 KiB × 8）估，最坏几 MB 量级 ——
  相对"漏登记导致重启读不到、每次启动重建基线并洗掉 7 份"，这个代价愿意付。
  漏登记**不报错**，所以 `tests/vue/useBackup.test.ts` 里那条把整条链跑真的用例是唯一的守法。
- **验收（已满足）**：旋转 8→7 只留最新 7 份（单测）；每日/换版/无动作三种判定各一条；
  槽内容读不出来时给明确提示且不动任何东西；设置面板列出时间 / 触发原因 / 大小 / 当时的应用版本
  并可一键恢复到确认块。顺带修掉一个真 bug：面板此前不在挂载时刷新列表，刚生成的自动备份
  要用户手动点一次"刷新"才出现。
- **未做（写明，别让"已满足"看起来比实际更远）**：面板那条链**没有 E2E**。上面四条里前四条由
  `tests/vue/useBackup.test.ts` 断言，"面板列出并可一键恢复"那半只到**胶水层 + 本机手动验证** ——
  `BackupSection.vue` 的模板与挂载时刷新没有被自动化覆盖。补它要先扩 `tests/e2e/tauri-stub.js`：
  自动备份整条链要求 `isDesktop`，桩得能在 Chrome 里把 `__TAURI_INTERNALS__` 与
  `read_doc`/`write_doc` 一起供上（会议历史那批已经这么做过，可照抄形状）。

### F-05 提醒与系统通知（P0，阶段 1 + 阶段 2 ✅ 已落地 2026-10-21；深链受平台限制，见下）
- **现状（改造前）**：全仓无 notification 能力；倒数日/生日/习惯/待办只能"看"。
- **阶段 1（已落地）**：`src/vue/reminders.ts` 纯判定（`now` 注入）+ `src/vue/useReminders.ts` 胶水。
  规则三条：倒数日就是今天 / 生日就是今天（闰日平年落 2/28，跟引擎走）/ 习惯过了设定时刻没打卡。
  **不做待办到期提醒**：`Todo` 没有截止日期字段 —— 不编不存在的东西。
  投递 = 顶栏下方一条可收起的**提醒横幅**；同一件事**一天只提醒一次**（稳定 key + 当日已提醒表落盘）；
  **静默时段只压投递、不压事实**（静默结束后同一天内补弹）。**默认不静默**（起止相同 = 关闭）——
  静默跨午夜时当天不再补，对"就是今天"的事件等于吞掉，所以让用户自己开。设置存本机不进备份。
- **阶段 1 验收（已满足）**：注入 now 跨越到期点恰好一条（单测）；重启不重复、且跨桌面 hydrate
  链（单测把 `createFileStorage → hydrateData → 新实例` 跑真）；静默内不弹、静默后补弹；
  坏存储/写失败不拦投递；E2E 种子倒数日 → 横幅出现 → 收起 → 刷新不再弹。
- **阶段 2（已落地，2026-10-21）**：桌面壳接 `tauri-plugin-notification`（Cargo + npm +
  capabilities 的 `notification:default`）；动态 import，网页版不进包。权限被拒 / 插件加载失败 /
  发送抛错一律静默降级（横幅兜底）。设置里多一个「同时发系统通知」开关（默认开、只桌面可见）。
  判定、去重、静默时段与阶段 1 完全共用 —— 只换了投递实现。
- **做不到的一条（写清楚，不假装完成）**：**点通知回到对应卡在 Windows 上做不到**。插件文档写明
  交互式 action（回传"点了哪一条"）只有移动端有；Windows 只能得到系统默认的"点一下把应用带到前台"。
  真深链要自己做 Toast COM 激活或换通道，单列。另一个已知显示事实：**开发态** Toast 用的是
  `powershell.exe` 的身份与图标，装成安装包后才显示 Modulo（插件文档原话）。
- **仍未做**：卡内角标（倒数日卡已在当天高亮、生日列表在当天带图标、习惯卡显示连续天数 ——
  这三处已是"看得见"，独立角标需要和现有视觉一起定形状）。

### F-06 数据迁移框架（P0，技术债）
- **现状**：`SCHEMA_VERSION=1`、`MIGRATIONS` 空表、`cardData` 无版本；加 `rows` 时未升版。
- **目标**：每个 key 独立版本 + 迁移表；迁移前自动备份；失败回滚并保留现场。
- **验收**：夹具 v1 → v2 迁移后再读回一致；迁移抛错时原文件不被破坏；CI 有迁移测试。

### F-07 网络策略单一来源（P0，安全）
- **现状**：允许/拒绝清单在 `packages/engine/src/watch.ts`、`src-tauri/src/net.rs`、
  `tauri.conf.json` 的 CSP、AI 白名单四处；已漂移（超时 5s vs 10s；CSP 缺东财）。
- **目标**：一份 `net-policy.json` 生成三处（引擎清单 / Rust 清单 / CSP），CI 断言一致。
- **验收**：改一处，三个消费方同步；任一不一致 CI 红；股票卡在桌面能实际取数。

### F-08 浮窗清单与标识（P1）
- **验收**：工作台显示"已浮出 N 张"；管理面板可收回/置顶/定位；浮窗关闭后标识消失。

### F-09 模块库搜索/分类/最近使用（P1）
- **验收**：54 张卡可按关键词与分类检索；最近使用置顶；无命中时有空状态。

### F-10 设置 IA + 首启引导（P1）
- **验收**：设置独立入口；六个分组；首启三步可跳过；"不再提示"可复位。

### F-11 安全收口（P1）
- **验收**：`launcher` 不再放行 UNC；未接线的 AI 命令要么有调用点、要么删除（CI 断言命令面与调用点一致）；

## 4. 非功能需求

| 类别 | 要求 | 现状 |
|---|---|---|
| 启动 | 冷启动到可交互 ≤ 1.5s（本机基线待测） | 未建预算 |
| 交互 | 拖拽每帧不重排版面 | 已有 `drag:budget` 门禁 |
| 写入 | 内容改动防抖 ≤ 300ms，避免每键写盘 | 现状每改必写（`cardData.ts` 深监听） |
| 内存 | 常驻 ≤ 300MB（20 张卡） | 未建预算 |
| 可靠性 | 读盘异常不得被当成"空数据"回落到 localStorage | 现状：读失败即置 `null`，若有 legacy 值会回写（`fileStorage.ts:113-126`）；磁盘已有数据时这是覆盖风险 |
| 隐私 | 无遥测上传；密钥只进钥匙串/本地文件，永不进备份 | 现状密钥未入备份，但 AI 命令面未接线 |
| 安全 | 网络策略单源、无 UNC、命令最小权限 | 见 F-07/F-11 |
