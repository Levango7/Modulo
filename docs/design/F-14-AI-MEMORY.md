# F-14 AI 记忆：它记得你是怎样的（v1）

状态：**v1 已落地**（第十五笔，2026-11-09）｜实现见 §12.73

## 这一笔解决的是哪个问题

主流 agent 应用都有这一格：你跟它说过「我偏好四象限」，下次开新对话它还知道。
在此之前，Modulo 的 AI 只有：**会话历史**（按会话、翻得到但不主动用）、**资料**（`@` 才进）、
**卡片引用**（`@` 才进）—— 没有一处是"跨对话、每次都生效"的。**记忆**补的就是这一格。

## 三条硬边界（刻意的）

1. **AI 永远提议、用户点头才记**：`memory.add` 也是动作白名单的一员，走同一套
   「照做 / 算了」确认与撤销栈纪律 —— 它不能在你不知道的时候给自己写小纸条。
2. **看得见、删得掉**：记忆不是暗箱 —— 设置 → 实验室里有清单，删除走两步（同会议记录）。
   存储格 `modulo.memory.v1` 登记进 `DATA_KEYS`（漏登记的症状是"记得住、重启就忘"）。
3. **写清楚"这是背景不是当前指令"**：注入的 head 里明写 —— 否则模型会拿一条旧偏好
   顶掉用户此刻的要求。

## 注入形状与预算

`memoryBlock(entries)` 拼进 system 块（**常驻**，同能力说明），与引用块、能力说明拼成
同一条 system。预算 `MEMORY_BLOCK_MAX = 800` 字：**超预算从最早的开始丢**（新的更重要）
并明说「更早的记忆没放下」—— 常驻注入的预算不能像滚雪球一样涨。

## 闸门与上限（都在纯层，逐条有测试）

- 单条 ≤200 字，**超长拒收不截断**（截断会改语义）；空的不收；
- **同一句话不重复记**（幂等：「这条已经记过了」）；
- 条数上限 40（满了给指路：「先去设置里删掉几条旧记忆」）；
- 盘上的文档不可信：逐条清洗、坏条目丢弃、读盘时超长只截。

## 落点（纯层 / 胶水 / 界面）

- 纯层 `src/vue/aiMemory.ts`：`parseMemoryDoc` / `serializeMemoryDoc` / `addMemory` /
  `removeMemory` / `memoryBlock` / `newMemoryId`；
- 胶水 `src/vue/useMemory.ts`（`createMemory`，与 `useKnowledge` 同一形状：构造读档、
  变更落盘）；App `provide('memory')`；
- 坞：`buildMessages` 多收一个 `memory` 参数（缺省 `[]` = 不注入，老调用点零改动）；
- 动作：`memory.add`（`aiActions.ts` 的一个 case + 执行器一行映射）；
- 界面：设置 → 实验室 → 「记忆」块（清单 + 两步删除）。

## 没做的（如实记）

- **不进完整备份、也不进多端同步** —— 与资料 / 会话历史同一条取舍（显式清单）；
- 没有「忘记」动作（删除只走设置界面 —— 破坏性动作不进白名单，同 §12.70 边界 ②）；
- 没有自动记忆（"它自己觉得该记就记"是另一层决定：未经确认写用户档案，不做）；
- 没有按会话分区（记忆是全局的 —— 分区会让"它还记不记得"变成靠猜）。
