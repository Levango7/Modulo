| # | 文档 | 回答的问题 | 状态 |
|---|---|---|---|

## 与已有文档的分工

- `docs/ARCHITECTURE.md`：**怎么造**（投影模型、五条不变量、历史栈、渲染取舍、发布链）。
- `docs/CARD-CATALOG.md`：**卡片有什么**（54 种卡的形态矩阵与交付状态）。
- `docs/AGENT-COORD.md`：**谁在动哪块**（多 agent 并行时的作业面与资源认领）。
- 本目录：**为谁做、做成什么样**。四件套里的数字不挂 `<!-- facts -->`（它们是设计判断，
  不是实跑事实）；涉及"当前实跑"的数字请引用 ARCHITECTURE 的 facts 行。

## 版本与决策

- 本文档集随产品决策更新；**定位与"会议线冻结"两条在 PRODUCT.md §9 的决策记录里标着
  "待维护者拍板"** —— 拍板后把状态改成"已定"，并在同一提交里更新四件套中受影响的段落。
- 设计判断与代码事实冲突时，以代码为准并修正文档；文档先于代码时，在 PR 描述里写明
  "这是目标态，落地见 F-xx"。
- 新增缺口条目必须带**验收判据**（FUNCTIONAL-SPEC §3 的格式），不接受"应该更好用"这类描述。
