## 1. 一句话定位（推荐）

> **Modulo 是一个会替你干活的桌面工作台：对 AI 说一句话，它把事办了；
> 产出不是一闪而过的聊天记录——是一屏随时在跑的东西。**

三句话展开：

| | |
|---|---|
| **对话即指令** | 不用找按钮、记菜单。说一句"把这个月的开销记上 / 盯紧这个页面的变化 / 把今天的会议记成要点"，它就去建那张卡、改那份数据。 |
| **界面即产出** | AI 的每个动作都落在一屏可排布的活界面上：55 种卡即收即用，随手脱离成常驻小窗；数据在这台机器上，没有账号，断网也能用。 |
| **一切可扩展** | 技能、插件、MCP 工具随接随用；画布、命令、快捷键全部向 agent 开放——它不只是会用，还会替你布置这一屏。 |

**差异化只说一句：别人的 AI 给你一段答案，Modulo 给你一个替你跑着的工作台。**

## 1.1 首屏文案规格（v0.3 —— 首启流 PR 的实现依据）

| 元素 | 文案 |
|---|---|
| 主标题 | **这一屏，交给 AI 布置。** |
| 副题 | 说一句话，它建卡、记账、总结、盯梢——产出留在你布置得明的桌面上。 |
| 动作一 | **让 AI 开始**（默认高亮） |
| 动作二 | 我从空白开始 |
| 动作三 | 先看模板（次级） |
| 底部小字 | 不用注册；数据在这台机器上。 |
| 禁区 | 不再有"第 1 步 / 共 3 步"的分步向导；不再一上来就摊出 8 张模板让人挑。 |

为什么是这个方向（而不是继续做"面板"）：本地小组件面板这个赛道（start.me / Windows 小组件 /
各种 dashboard 模板）在 2024–26 已被 AI 原生产品全面挤压，增量用户不再为"漂亮的 widgets 板"付钱；
而 AI 产品的差距恰在水面之下——它们的输出是一去不回的文本。Modulo 已经做出来的东西
（布局引擎 / 55 张卡 / 原生卡扩展协议 / 浮窗 / 命令面板 / 本地优先）
组合出的形态恰好是 agent 输出**落地成活界面**的那一块，且没有第二个产品占住。

## 2. 三个候选定位与取舍

| 候选 | 目标用户 | 已经具备的 | 还缺什么 | 判断 |
|---|---|---|---|---|
| **A' AI 原生的桌面工作台**（2026-11-05 起主推） | 用 codex / ChatGPT work / Claude desktop / qoder / trae 那代工具的知识工作者与技术用户 | AI 对话坞（流式 / @卡片摘录 / 上下文预算 / 取消）、55 张可被 agent 操作的活卡、扩展注册表（manifest / 权限 / 沙箱）、命令总线、浮窗、本地优先 | 外壳（聊天任脊柱的左栏 / 模式 / Session）、composer 全控件（模型 / 思考等级 / 上下文 / 权限 / 文件）、skills / MCP / cronjob / 知识库 | 叙事与 demo 一眼可懂；独占差异点站得住 —— **主战场** |
| **B 技术用户的值守/监控能力底座** | 交易者、值班运维、独立开发者 | 联网卡 + 系统监控 + 浮窗 + 一屏编排 | 提醒、签名、winget、数据导出 | 不单独作战，**整体降格为 A' 的能力底座**：同样的卡，由 agent 来布置与更新 |
| **C 会议/截图记录器** | 会议多的职场人 | 截图五命令、窗口预览、WASAPI + ASR + 转写 | 竞品极强（Otter / 飞书妙记 / Teams）、模型体积、合规 | **冻结为可选模块**，等 A' 站住后并入 agent 工具链（会议 → 纪要卡 → 待办） |

**取舍结论**：主定位取 A'；B 的工具价值保留但改为被 agent 驱动（不再作为独立卖点叙事）；C 冻结。
转向的执行分期（换壳 → 首启 → 左栏与 AI 脊柱 → 生态位）见 §9。

## 3. 人物画像（3 个，用于拒绝需求）

1. **盯盘者**：白天开着行情与新闻，要求"一屏、常驻、不打断"。在意浮窗置顶、刷新频率、
   断网时的表现，不在意主题与动画。
2. **值班运维**：电脑上常驻探针与系统监控，要求"异常一眼看见"。在意连通性探测的历史与告警、
   系统指标的稳定性，不在意卡片美观。
3. **信息收集者 / 独立开发者**：RSS + 网页取数 + GitHub + HN，要求"把散落的信息收进一屏"。
   在意取数规则的可配置性、数据可导出，不在意协作。

反面画像（明确不服务）：需要多人协作编辑的团队、需要手机端随时记录的用户、
需要开箱即用模板库的非技术用户。

## 4. 核心任务（JTBD）

1. 早上打开 → 一屏看到今天该看的信息（行情、订阅、系统、待办）。
2. 发现异常 → 把某张卡浮到桌面常驻，边工作边盯。
3. 信息要留档 → 一键导出 / 自动备份，换机或重装能完整恢复。
4. 到点该做事 → 系统通知提醒（待办到期、倒数日、习惯）。
5. 布局要改 → 键盘或拖拽都能完成，改坏了能撤销。

## 5. 非目标（写死，避免范围蔓延）

- 不做多人协作 / 云端文档 / 账号体系；
- 不做移动端（12 个月内）；
- 不做会议记录器的正面竞争（C 线冻结）；
- 不做通用笔记库（不追求 Markdown 双链、知识图谱）；
- 不承诺"任何网页都能嵌"（安全边界优先于功能）。

## 6. 成功指标（先定口径，再谈增长）

当前**没有任何遥测**（全仓无 sentry/telemetry），这是隐私上的优点、也是产品上的盲区。
建议按"本地统计 + 用户主动导出"的方式补，不默认上传：

| 指标 | 口径 | 用途 |
|---|---|---|
| 分发 | winget 安装数 + GitHub Release 下载数 | 判断是否值得继续投入 |
| 留存 | 7 日内再次启动（本地记录，用户可导出） | 判断"打开一次就吃灰" |
| 卡使用分布 | 每张卡的启用数 / 日活（本地） | 决定下沉/删除哪些卡 |
| 可靠性 | 崩溃/白屏次数（本地计数） | 优先级最高的体验指标 |
| 启动时延 | 冷启动到可交互（本机探针已有基础） | 判定性能预算是否达标 |

## 7. 待验证的假设（按风险排序）

1. **B 类用户真的愿意用桌面面板而不是浏览器标签页/副屏**（验证方式：找 5 个目标用户试用两周）。
2. **"本地优先、无账号"是卖点而不是障碍**（验证方式：访谈中对比"加同步"的意愿）。
3. **54 张卡里真正被用的是少数几张**（验证方式：卡使用分布；若成立，广度应让位于深度）。

## 8. 与三条产品线的关系

| 线 | 角色 | 投入策略 |
|---|---|---|
| 主应用（Windows 桌面） | 用户价值载体 | 全部产品投入 |
| `@levango7/engine`（npm） | 布局引擎的可复用资产 | 维持发布链与 API 稳定，不主动扩功能 |
| 会议/截图/ASR | 已验证的技术能力 | 冻结；作为可选模块或独立发行版评估 |
